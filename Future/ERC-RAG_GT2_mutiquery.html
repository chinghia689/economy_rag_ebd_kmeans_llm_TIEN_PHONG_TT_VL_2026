LLM-guided Multi-Vector Energy-based Retrieval Clustering for RAG in Vietnamese Economy Chatbots

Abstract

Retrieval-Augmented Generation (RAG) improves the factual reliability of Large Language Model (LLM) chatbots by grounding generation in external documents. Conventional dense retrievers, however, usually encode a complex question as one vector and rank documents independently by cosine similarity. We present GT2-MultiQuery ERC-RAG, an Energy-based Retrieval Clustering framework for Vietnamese economic question answering. An LLM first decomposes or reformulates the original question into multiple focused queries whose embeddings form a multi-point query distribution. Each query retrieves candidates from ChromaDB; deduplicated candidates are clustered by K-Means, with the number of clusters selected by silhouette score. Energy distance compares the query distribution with every document-cluster distribution, and the minimum-energy cluster is filtered by an LLM before response generation. Experiments on 1,000 VNEIQAD questions evaluate m = 2, 3, 4, and 5 total query vectors. Performance increases consistently with m. The m = 5 configuration achieves BLEU-2 = 0.71, ROUGE-2 F1 = 0.74, cosine similarity = 0.96, MRR = 0.68, Hit@5 = 0.70, and NDCG@5 = 0.87. The results indicate that complementary query vectors improve both answer generation and retrieval effectiveness in Vietnamese economic RAG.

Keywords: Vietnamese question answering; retrieval-augmented generation; multi-query retrieval; query decomposition; energy distance; K-Means clustering; economic chatbot.

1. Introduction

Chatbots are software systems designed to simulate human conversation. Modern systems commonly use Large Language Models, which provide fluent generation but may produce unsupported or outdated statements. Retrieval-Augmented Generation mitigates this limitation by retrieving evidence from an external source and conditioning the response on that evidence.

RAG is particularly important in economic question answering. A mismatch in time period, market, unit, indicator, or organization can change the meaning of a financial claim. Vietnamese economic questions are also frequently compound: one sentence may contain several entities, numeric slots, temporal constraints, and causal relations. A single dense vector compresses these information needs into one point and may emphasize only the dominant semantic aspect.

GT2_mutiquery extends Energy-based Retrieval Clustering RAG from a single query representation to a multi-vector query distribution. An LLM creates focused query variants while retaining the original question. Candidate documents are retrieved for every query, deduplicated, and grouped into semantic clusters. The system selects the cluster whose document distribution has the smallest energy distance from the query-vector distribution.

  • LLM-guided query construction that preserves the original question and exposes complementary entities, constraints, and relations.
  • A distribution-to-distribution retrieval objective whose query self-distance remains meaningful for multiple vectors.
  • A controlled evaluation of 2–5 total query vectors on 1,000 Vietnamese economic questions.
  • An implementation-aligned pipeline covering candidate union, deduplication, silhouette-guided K-Means, energy scoring, document grading, and grounded generation.

2. Background and Motivation

2.1 The single-vector bottleneck

A conventional dense retriever embeds question q as one vector f(q) and returns top-ranked chunks under cosine similarity. This is efficient but assumes that one embedding represents all information needs. Evidence about a company, date, price movement, and requested numeric value may occupy different semantic neighborhoods.

2.2 Multi-query representation

Let m be the total number of query vectors, including the original question:

(1)Q = {q, q1, q2, …, qm−1},   2 ≤ m ≤ 5.

The original query carries global intent; generated parts provide focused retrieval views. Unicode normalization, validation, and case-insensitive deduplication remove invalid or repeated variants. Deterministic fallbacks supplement malformed or insufficient LLM output.

2.3 Energy distance

Energy distance measures discrepancy between distributions using expected pairwise Euclidean distances (Székely & Rizzo, 2013; Rizzo & Székely, 2016). Query embeddings form empirical distribution X; document embeddings in cluster j form Yj:

(2)X = {f(qi)}mi=1,    Yj = {f(dr) : dr ∈ Cj}.

Unlike single-vector ERC-RAG, a multi-query distribution generally has non-zero within-query distance. Cluster selection can therefore account for the semantic spread shared by the query variants.

3.1 LLM-guided query construction

The splitter instructs the LLM to retain important entities, dates, units, numeric slots, and relations; avoid unsupported assumptions; and return a JSON string array. The original question is always retained. In the controlled runs, configuration m contains the original plus m − 1 generated query parts.

3.2 Candidate union and deduplication

Each query independently retrieves its top 40 ChromaDB chunks by cosine similarity. Results are unioned and deduplicated using source metadata, page metadata, and a content hash:

(3)D* = Dedup( ⋃mi=1 TopN(qi, D) ),   N = 40.

3.3 Silhouette-guided clustering

Candidate embeddings are clustered by K-Means. For feasible k from 2 through min(10, |D*| − 1), the implementation uses random_state=42 and n_init="auto", selecting the highest silhouette score:

(4)k* = arg maxk ∈ {2,…,min(10,|D*|−1)} Silhouette(KMeans(D*, k)).

3.4 Multi-vector energy scoring

For |X| = m and |Yj| = nj, the implementation uses:

(5)ED(X,Yj) = max(0,  2/(mnj) Σa,b ‖xa−yb‖2 − 1/m² Σa,c ‖xa−xc‖2 − 1/nj² Σb,d ‖yb−yd‖2).

Distances are Euclidean. Clipping at zero prevents small negative estimates caused by finite samples or floating-point error. For m > 1, the query self-distance term does not vanish.

(6)j* = arg minj ED(X,Yj),    C* = Cj*.

3.5 Relevance filtering and generation

Documents in the minimum-energy cluster are evaluated in one batch LLM call. Only chunks judged relevant are inserted into the generation prompt with the original question.

4. Algorithm

Algorithm 1 · GT2-MultiQuery Energy-based Retrieval Clustering RAGDistribution-to-distribution cluster selection with LLM-guided queries
Input: question q; collection D; embedding model f; total vectors m ∈ {2,3,4,5}; retrieval size N = 40.
Output: grounded response r.
  1. Normalize the Vietnamese question q.
  2. Generate m − 1 focused queries; validate, deduplicate, and apply fallback queries if needed.
  3. Construct Q = [q, q1, …, qm−1] and embed it as distribution X.
  4. Retrieve top-40 chunks independently for each query.
  5. Union and deduplicate candidates; embed their contents.
  6. Fit K-Means for each feasible k and select k* by silhouette score.
  7. Compute ED(X,Yj) for each document cluster.
  8. Select the minimum-energy cluster.
  9. Apply LLM relevance grading to documents in that cluster.
  10. Generate and return r from the question and filtered evidence.
Implementation correspondence. Query construction is implemented by LLMAutoSplitter; candidate union, K-Means, and cluster selection by MultiVectorERC; and Equation (5) by energy_base_distance. The repository spelling Gt2_mutiquery is retained for compatibility.

5. Related Work

5.1 Energy-based retrieval

Energy-Based Models assign low energy to compatible configurations and high energy to incompatible ones (LeCun et al., 2006). Energy-based methods have been applied to translation reranking (Bhattacharyya et al., 2021), knowledge-grounded dialogue retrieval (Cai et al., 2025), and reliability modeling in medical RAG (Shankar et al., 2025). Energy distance is instead a nonparametric discrepancy based on pairwise distances between distribution samples.

5.2 Multi-query RAG

Query augmentation generates alternative retrieval views to reduce sensitivity to question wording. RAG-Fusion combines multiple generated queries and reciprocal-rank fusion (Rackauckas, 2024). GT2_mutiquery retains the query embeddings as distribution X and selects a semantic document cluster by energy distance instead of fusing document ranks alone.

5.3 Clustering and reranking

Clustering can reduce redundant context and expose structure among retrieved chunks. Cross-encoder and LLM rerankers usually operate on individual query–document pairs (Nogueira & Cho, 2019; Sun et al., 2023). The proposed method evaluates a cluster collectively against multiple query representations, then applies an LLM grader.

6. Experimental Protocol

6.1 Dataset and index

Evaluation uses the Vietnamese Economy Information Database (VEID) and 1,000 Vietnamese Economic Question Answering Dataset (VNEIQAD) question–answer pairs. Documents are segmented with RecursiveCharacterTextSplitter using chunk size 600 and overlap 80, producing 120,165 chunks in ChromaDB.

Questions and chunks are encoded by intfloat/multilingual-e5-base into 768-dimensional embeddings, following the E5 query: and passage: convention.

6.2 Configurations

Four controlled settings are evaluated: m = 2, 3, 4, and 5 total query vectors. Each includes the original question and m − 1 query parts. Each scored configuration contains exactly 1,000 non-empty question rows. GPT-5.0-mini is used for query construction, document grading, and response generation.

6.3 Metrics

Generation

BLEU-2 measures bigram precision. ROUGE-2 Recall, Precision, and F1 measure bigram overlap. Cosine Similarity measures semantic answer alignment.

Retrieval

MRR rewards early relevant contexts. Hit@5 measures whether a relevant context occurs in the top five. NDCG@5 measures discounted ranking quality.

Workbook handling. Each scored workbook contains 1,000 question rows followed by one numeric summary row and one repeated-label row. The experimental sample size is 1,000; the trailing rows are not observations.

7.1 Effect of query-vector count

All metrics improve monotonically or remain stable as m increases. From m = 2 to m = 5, BLEU-2, ROUGE-2 F1, MRR, and Hit@5 each rise by 0.09; NDCG@5 rises by 0.04; cosine similarity rises from 0.95 to 0.96. Agreement between generation and retrieval metrics supports the hypothesis that complementary query views improve evidence discovery rather than only changing answer phrasing.

7.2 Baseline comparison

The average multi-query configuration obtains BLEU-2 = 0.66 and ROUGE-2 F1 = 0.69. Relative to the strongest Energy-based Reranking row, these are absolute gains of 0.05 and 0.20. The m = 5 setting reaches 0.71 and 0.74. Retrieval metrics are unavailable for the external baselines, so no direct MRR, Hit@5, or NDCG@5 comparison is claimed.

7.3 Interpretation and cost

Increasing m explores more semantic neighborhoods. Deduplication limits repeated evidence, while energy distance selects the cluster whose cross-query proximity and internal geometry best match the query distribution. The tested range identifies m = 5 as the best quality setting, but larger m also increases LLM, embedding, vector-search, and clustering cost.

8. Limitations and Threats to Validity

  • Model coupling: external baseline rows use different generators, so gains cannot be attributed solely to retrieval architecture.
  • No cost report: workbooks measure quality, not latency, token use, or vector-search cost.
  • Single domain and language: generalization beyond Vietnamese economic data requires evaluation.
  • Splitter dependence: redundant or broad variants can add noise despite validation and fallbacks.
  • Statistical inference: paired confidence intervals and per-question significance tests should be added.

9. Conclusion

GT2-MultiQuery ERC-RAG represents a user question through the original and LLM-generated focused queries, retrieves evidence for every query, clusters deduplicated candidates, and selects context by minimizing energy distance between query and document-cluster distributions. On 1,000 VNEIQAD questions, performance improves consistently from two to five query vectors. The best tested setting achieves BLEU-2 = 0.71, ROUGE-2 F1 = 0.74, cosine similarity = 0.96, MRR = 0.68, Hit@5 = 0.70, and NDCG@5 = 0.87.

Future work should evaluate adaptive per-question selection of m, latency and token cost, paired statistical tests, and alternative distributional distances such as Maximum Mean Discrepancy and Wasserstein distance.
